## 1. `python`을 입력하면 Microsoft Store가 열림

**원인**: Windows에는 `python`이라는 이름의 가짜 바로가기(Store 설치 안내)가 있습니다.

**해결**: 대신 `py`를 쓰세요. python.org에서 설치하면 함께 깔리는 런처입니다.
```bat
py --version
py -m pip install -r requirements.txt
```

## 2. 한글이 깨지거나 `UnicodeEncodeError`

**원인**: Windows 콘솔의 기본 인코딩이 UTF-8이 아닙니다.

**해결**: `-X utf8` 옵션을 붙여 실행하세요.
```bat
py -X utf8 scripts/collect.py
```
`start-site.bat`은 `chcp 65001`로 콘솔을 UTF-8로 바꾼 뒤 실행합니다.

## 3. `.env`에 키를 넣었는데 비어 있다고 나옴

**원인**: 편집기에서 **저장하지 않았습니다.** 탭 제목 옆에 ● 표시가 있으면 저장 안 된 상태입니다.

**해결**: `Ctrl+S`로 저장하고, 서버를 껐다 다시 켜세요. 서버는 시작할 때만 `.env`를 읽습니다.

> 키가 들어갔는지는 **값을 출력하지 말고** 길이나 앞 몇 글자만 확인하세요. 서버를 켜면 `Gemini: ON / Firecrawl: ON`처럼 상태만 보여 줍니다.

## 4. Gemini 404 / 429 / 503

키가 맞아도 **모델에 따라** 오류가 납니다. (2026-10-13 기준, 무료 키)

| 코드 | 뜻 | 오늘 겪은 모델 |
|---|---|---|
| 404 | 이 모델은 새 사용자에게 제공 안 함 | `gemini-2.5-*` |
| 429 | 할당량 없음 / 초과 | Pro 계열 |
| 503 | 서버 혼잡 | Flash 계열 (자주) |

**해결**: 여러 모델을 순서대로 시도하는 **자동 전환**을 넣었습니다. `.env`에서 순서를 바꿀 수 있습니다.
```
GEMINI_MODEL=gemini-flash-latest
GEMINI_FALLBACK_MODELS=gemini-flash-lite-latest,gemini-3.5-flash-lite,gemini-3.1-flash-lite
```

> **"키 확인"과 "기능 확인"은 다릅니다.** 모델 목록이 잘 나와도 실제 요약 요청은 실패할 수 있으니 끝까지 호출해 보세요.

## 5. AI가 "가격이 비정상"이라고 답함

**원인**: AI는 **과거 가격을 학습**했습니다. 올해 크게 오른 RAM 가격을 보고 이상하다고 판단했습니다.

**해결**: 질문할 때마다 **오늘 날짜(한국 시간)** 와 "이 가격은 오늘 다나와에서 조회한 실제 시세"라는 설명을 함께 보냅니다. (`_core.py`의 `PRICE_NOTE`)

> AI에게는 **AI가 모르는 최신 정보를 직접 알려 줘야** 합니다.

## 6. 다나와 검색 결과가 가끔 0건

**원인**: 같은 검색어도 다나와가 가끔 빈 결과를 돌려줍니다.

**해결**
- 0건이면 잠시 쉬고 **다시 시도**합니다.
- 결과가 이전 수집의 절반도 안 되면 **기존 파일을 덮어쓰지 않습니다.** 좋은 데이터를 지키는 안전장치입니다.

## 7. 네이버·쿠팡 스킬이 404 / 403

**원인**: 두 스킬은 k-skill 제작자가 운영하는 **중계 서버(프록시)** 를 거칩니다. 그 서버 쪽 문제였습니다. (네이버 404 "Invalid search api", 쿠팡 403)

**해결**: 우리 쪽에서 고칠 수 없습니다. 수집기는 실행할 때마다 두 서버 상태를 확인하고, 복구되면 자동으로 데이터를 저장합니다. 결과는 `data/collection_log.json`의 `source_status`에 남습니다.

## 8. 배포판에서 다나와가 403

**원인**: 다나와는 Vercel 같은 **데이터센터 IP의 접속을 막습니다.** 서울 리전으로 옮겨도 같았습니다. 내 PC(가정용 인터넷)에서는 잘 됩니다.

**해결: 우회하지 않고 설계를 바꿨습니다.**
```
[이전] 사용자 → Vercel 서버 → 다나와 (403 차단)
[이후] 내 PC → 다나와 → parts.json → GitHub → Vercel → 사용자
```
- 배포판은 `DANAWA_LIVE=0`으로 실시간 검색을 끄고, 화면에 이유를 안내합니다.
- 프록시를 거치거나 IP를 바꿔 차단을 피하는 방법은 **상대 서비스의 의사를 무시하는 것**이고, 스킬 이용 규칙에도 어긋납니다.

> **막혔을 때 "어떻게 뚫을까"보다 "다른 길이 있을까"를 먼저 생각하세요.**

## 9. `vercel env add`가 멈춘 채로 있음

**원인**: 이 명령은 값을 **키보드 입력**으로 받으려고 기다립니다. 자동화 환경에서는 입력이 오지 않아 멈춥니다.

**해결**: 가장 쉬운 방법은 **Vercel 웹 대시보드**에서 넣는 것입니다.
`Project → Settings → Environment Variables → Add`

명령줄로 하려면 값을 표준 입력으로 넘깁니다. 값이 화면이나 명령 기록에 남지 않게 주의하세요.

## 10. Vercel이 GitHub 저장소에 연결되지 않음

**증상**: `vercel git connect`가 실패. 그래서 GitHub에 올려도 자동 배포가 안 됨.

**원인**: Vercel GitHub 앱이 **새로 만든 비공개 저장소에 접근할 권한**이 없습니다.

**해결**
1. https://github.com/settings/installations → **Vercel** → Configure
2. **Repository access**에 `dragonball-pc` 추가 → Save
3. `pc-build` 폴더에서 `vercel git connect`

그 전까지는 `vercel deploy --prod`로 직접 배포하면 됩니다.

## 막혔을 때 확인 순서

1. **오류 메시지 전체를 읽는다.** 숫자 코드(401, 403, 404, 429, 503)가 가장 큰 힌트입니다.
2. **어디서 난 오류인지 나눈다.** 내 코드? 외부 서비스? 내 PC 환경?
3. **가장 작은 단위로 다시 해 본다.** 사이트 전체 대신 API 하나만 호출해 보기.
4. **고친 뒤 실제로 다시 실행해 확인한다.**

| 코드 | 뜻 | 먼저 볼 곳 |
|---|---|---|
| 400 | 요청 형식이 틀림 | 입력값 |
| 401 | 인증 실패 | 접근 코드, API 키 |
| 403 | 접근 금지 | 상대 서비스의 차단, 권한 |
| 404 | 없음 | 주소, 모델 이름 |
| 429 | 너무 많이 요청함 | 잠시 기다리기, 할당량 |
| 5xx | 상대 서버 문제 | 잠시 후 재시도 |
